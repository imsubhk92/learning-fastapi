# 5. Starlette, middleware and network protocols

The correct name is **Starlette**. It is the ASGI toolkit beneath FastAPI,
providing routing, request/response abstractions, middleware, WebSockets,
lifespan, background tasks and testing tools. FastAPI adds its API-oriented
contracts and dependency system on that foundation.
[Starlette applications](https://starlette.dev/applications/).

## Routing and request context

Starlette has `Route`, `WebSocketRoute`, `Mount`, and routers. In FastAPI we use
`APIRouter` and `include_router` to organize endpoints without creating multiple
servers. Our `orders` router applies a shared prefix and tag. Mounted sub-apps
are a different design: they can have their own application configuration and
documentation. [Routing](https://starlette.dev/routing/).

`Request` exposes method, URL, headers, query parameters and state. Accessing raw
request data bypasses the convenience of a declared body model; if you parse it
yourself, validation becomes your responsibility. Our development route exposes
only a small allowlist because blindly reflecting headers can expose tokens.

## Middleware and ASGI events

Our [request middleware](../app/middleware.py) receives `(scope, receive, send)`.
For HTTP it wraps `send`, adding headers on `http.response.start`. It passes
WebSocket/lifespan scopes through unchanged and does not buffer body chunks.

Per-request state belongs inside `__call__`; mutable instance state can leak
between concurrent requests. Middleware order matters: Starlette's outer error
middleware and inner exception middleware serve different jobs. Our headers
appear on normal responses and handled errors such as 404/422. An unhandled
500 generated by the outer error layer may bypass this inner wrapper.
[Middleware and its ordering](https://starlette.dev/middleware/).

`X-Response-Time-Ms` measures elapsed time until response headers begin. It does
not measure the total stream duration, network transit, or client rendering.
`X-Request-ID` is generated by the service; a client-provided ID is not trusted
or reflected. Adding the header alone does not implement trace collection.

## Lifespan versus a request dependency

`lifespan` in [main.py](../main.py) creates the repository before serving traffic
and removes it during shutdown. This happens once per worker. A later async
HTTP connection pool or loaded model could live here. A request-scoped database
session instead belongs in a dependency with `yield` and cleanup. Do not create
heavy resources at module import time merely because it is convenient.
[FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/),
[dependencies with yield](https://fastapi.tiangolo.com/tutorial/dependencies/dependencies-with-yield/).

Using `with TestClient(app)` runs lifespan in tests. An HTTPX2 `ASGITransport`
does not run lifespan itself; our async test enters the app's lifespan context
explicitly. With current Starlette, the development dependency is `httpx2`;
older tutorials use `httpx`. The route code is independent of that testing client.
[Starlette TestClient](https://starlette.dev/testclient/).

## HTTP, HTTPS, WS and WSS

HTTP defines the request/response protocol. HTTPS adds TLS encryption and server
identity. `ws://` is an unencrypted WebSocket connection; `wss://` uses TLS.
Starlette handles application-level protocols through ASGI. TLS is normally
terminated by the server or an ingress/reverse proxy, rather than by a route.
ASGI support is not a guarantee of every HTTP version in every server.
[FastAPI HTTPS deployment](https://fastapi.tiangolo.com/deployment/https/).

In a typical deployment, the browser uses HTTPS to a proxy, which forwards to
an internal Uvicorn listener. Configure trusted proxy addresses and forwarded
headers deliberately so redirects and generated URLs see the correct scheme.
Do not trust forwarded headers from arbitrary clients.
[Behind a proxy](https://fastapi.tiangolo.com/advanced/behind-a-proxy/).

## Our WebSocket protocol

Start the API, then run `uv run --locked python examples/websocket_client.py`.
The example connects to `ws://127.0.0.1:8001/ws/orders/3`.

| Stage/message | Server behavior |
| --- | --- |
| Connect to an existing positive ID | Accept and send `{"event":"order_snapshot","order":{...}}` |
| Text `refresh` | Send the latest stored order snapshot |
| Text `close` | Close normally with code 1000 |
| Other text | Close with code 1008 |
| Binary message | Close with code 1003 |
| Missing/deleted order | Reject or close with 1008; before accept a real server may deny the HTTP upgrade |
| Client disconnect | Exit the handler normally |

This teaches connection lifecycle, not automatic notifications: changing an
order with PATCH does not broadcast to connected clients. A client sends
`refresh` to see the update. OpenAPI does not describe this socket protocol.
[FastAPI WebSockets](https://fastapi.tiangolo.com/advanced/websockets/).

For a real event service, add identity/authorization, browser Origin validation,
message and connection limits, heartbeat/idle policy, bounded buffering and a
shared event transport. HTTP CORS middleware does not protect WebSocket
handshakes in the same way it governs browser HTTP requests.

## Other useful Starlette tools

`CORSMiddleware` handles browser cross-origin HTTP access. Configure exact
origins when needed; origin includes scheme, hostname and port. CORS does not
authenticate callers or block command-line clients. We have no separate browser
frontend, so this app does not enable CORS.
[CORS](https://fastapi.tiangolo.com/tutorial/cors/).

`TrustedHostMiddleware`, `HTTPSRedirectMiddleware`, sessions, file/stream
responses, static files and templates are useful when requirements call for
them. Adding an HTTPS redirect without a correctly configured proxy can cause
redirect loops. These optional tools are mapped in the
[feature guide](09-feature-map.md), rather than installed indiscriminately.
